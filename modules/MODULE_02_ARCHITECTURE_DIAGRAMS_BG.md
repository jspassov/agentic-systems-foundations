# Модул 2 — четири работни архитектурни схеми

Това са **текстови реконструкции на четирите показани в разговора схеми**, съхранени като редактиращ се Mermaid код. Не са генерирани нови графични assets. Целта им е да останат reusable в GitHub и да могат да се преработват за презентация.

## 1. „Първо научи AI как да работи. После го научи да работи сам.“

~~~mermaid
flowchart TD
    A["1. Framework Thinking<br/>Цели · Контекст · Източници · Правила · Критерии за качество"]
    B["2. Agentic-ish Assistant<br/>ChatGPT Project · GitHub · Google Drive · Prompts · Workflows"]
    C["3. Validation & Improvement<br/>Реални задачи · Проверка · Корекции · Възпроизводимост"]
    D["4. Automation<br/>График · No-code/low-code · APIs, когато са необходими"]
    A --> B --> C --> D
~~~

**Смисъл:** не започваме от автоматизацията. Първо изграждаме рамката, после изпълняваме и проверяваме реални задачи.

## 2. Примерна архитектура за бъдеща автоматизация

~~~mermaid
flowchart TD
    G["GitHub — Framework<br/>Знания · Правила · Workflows · Конфигурация"]
    N["Automation Engine (пример: n8n)<br/>Triggers · Scheduling · Integrations · Execution"]
    A["AI — Reasoning Engine<br/>Анализ · Предложения · Генериране · Проверка"]
    H["Human Approval<br/>Контрол върху важните решения и публикуването"]
    G <--> N
    N <--> A
    A --> H
~~~

**Смисъл:** n8n е примерен изпълняващ механизъм, а не архитектурно изискване. За реални интеграции добавяме контрол върху правата, входовете и действията.

## 3. Същата идея с локален модел

~~~mermaid
flowchart TD
    G["GitHub — Framework<br/>README · AGENTS · Workflows · Knowledge"]
    O["Orchestration (пример: n8n)<br/>Зареждане на правила · Контекст · Инструменти · Контрол"]
    L["Ollama API + Local LLM<br/>Qwen · Llama · Gemma · Друг съвместим модел"]
    R["Резултат"]
    V["Проверка"]
    D{"Действието разрешено ли е?"}
    H["Човешко одобрение при необходимост"]
    X["Действие или отказ"]
    G --> O --> L --> R --> V --> D
    D --> H --> X
~~~

**Смисъл:** локалният LLM не изменя целта и политиките на Framework-а; той сменя средата за изпълнение. Необходимо е отделно тестване на tool calling, качество, ресурси и защита на данните.

## 4. Framework, независим от AI платформата

~~~mermaid
flowchart TD
    F["Нашият Framework<br/>Правила · Знания · Процеси · Критерии"]
    C["ChatGPT"]
    A["AnythingLLM"]
    D["Dify / n8n"]
    RC["Облачен модел в ChatGPT"]
    RL["Локален или облачен LLM според интеграцията"]
    RD["Свързан LLM runtime според платформата"]
    F --> C
    F --> A
    F --> D
    C --> RC
    A --> RL
    D --> RD
~~~

**Смисъл:** можем да използваме общи принципи и знание в няколко платформи. Това **не** означава автоматична съвместимост на файловете или че ChatGPT Project може да смени своя runtime с Ollama. За всяка среда са нужни bootstrap, adapter и проверка.

## Статус на схемите

Схема 1 е **образователна последователност**. Схеми 2–4 са **варианти за бъдеща реализация**, без ангажимент към n8n, AnythingLLM, Dify, Ollama или друга конкретна технология. Нито една от тях не удостоверява вече работещ production pipeline.
